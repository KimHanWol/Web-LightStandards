# 배포 자원 용량 기준

기준은 `config/asset-budgets.json`에서 관리한다. KB는 1,000바이트 기준이다.

| 자원 | 개별 파일 상한 |
| --- | --- |
| 이미지 | 200KB |
| SVG | 50KB |
| 폰트 | 100KB |
| CSS | 120KB |
| JavaScript | 150KB |
| HTML | 250KB |
| JSON·XML 및 기타 파일 | 500KB |

새 원고 이미지는 서버에서 WebP로 변환하며 160KB를 목표로 압축한다. 가로·세로는 각각 최대 1,280px이고, 화질과 크기를 단계적으로 조정해 200KB 이하로 만든다. 다운로드 원본은 최대 8MB·2,000만 화소로 제한한다. 이는 방문자에게 전송하는 파일 상한과 별개다.

`npm run assets:optimize`는 이미 보관한 WebP 중 상한을 넘는 파일도 최적화한다. 실제 화면 캡처는 승인 당시 파일 해시를 유지해야 하므로 자동으로 덮어쓰지 않으며, 큰 캡처는 최적화 후 검토·승인해야 한다. 정적 PNG·JPEG 등도 배포 용량 검사를 통과해야 하며 원고 가져오기를 통하면 WebP로 자동 변환된다.

GitHub 배포는 원고 가져오기 → 이미지 최적화 → 결과 보관 → 빌드 → 배포 자원 검사 순서다. 첫 화면에서 지연 로딩 없이 요청하는 자체 이미지의 합계는 페이지당 450KB로 제한한다. 화면 아래 이미지는 기존 지연 로딩을 유지한다. 사이트 전체 용량은 글이 늘면서 자연스럽게 증가하므로 전체 저장 용량에 일률적인 상한을 걸지 않는다.

검사는 사이트가 직접 제공하는 파일에 적용한다. 쿠팡 등 외부 광고 서버가 전송하는 파일의 용량은 강제할 수 없으며, 광고는 화면 가까이에 들어올 때 불러오고 공통 스크립트를 한 번만 요청한다.
