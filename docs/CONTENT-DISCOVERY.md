# 관련 글과 대표 글

2026-10-16 사용자가 관련 글 연결과 대표 글 선정을 승인했다. 실용 자료 보강은 설계를 더 검토하며, 검색 성과 점검과 광고 성과 비교는 미룬다. 이번 변경에서 원고 생성·이미지 생성·주기 실행을 추가하지 않는다.

## 관련 글 연결

`config/reading-paths.json`은 실제 발행된 글의 읽기 경로다. 새 원고의 작성 분야를 고정하는 규칙이 아니다. 기존 Topic Map의 질문·제목·다루는 항목을 함께 활용한다.

- 검토한 다음 작업 관계를 가장 먼저 선택한다. 포토 백업 → 앨범·내보내기·공유, 드라이브 공유 → 시트 보호 등이 해당한다.
- 같은 앱·작업 묶음의 글을 후보로 삼고 작업 순서와 질문·다루는 항목의 관련성을 반영한다. 카테고리가 같다는 이유만으로 최신 글을 붙이지 않는다.
- 원고가 승인됐고 실제 발행 시점이 지난 글만 연결한다. 자기 자신, 같은 intent, 테스트·미승인·미래 글과 중복 ID는 제외한다. 맞는 후보가 없으면 추천을 숨긴다.
- 본문 중간의 완결된 절 뒤에 다음 글 1개를 표시하고, 나머지는 하단 카드로 보여 준다. 같은 링크를 두 영역에 반복하지 않는다. 광고와 같은 절에는 넣지 않는다.
- 승인 원고 JSON·Markdown과 revision은 바꾸지 않는다. 공통 템플릿에서 링크를 만들므로 기존 글과 새 글 모두 빌드 때 갱신되며 추가 AI 호출이 없다.

현재 글에 근거한 묶음은 크롬, 윈도우, 지메일, 스프레드시트, 사진 정리, 지도·여행 준비, 생활 가전 관리다. 앱의 동일 intent 접두어로 발행된 새 글은 해당 앱 묶음에 자동 포함된다. 새로운 분야는 실제 발행 글을 확인한 뒤 읽기 경로를 추가한다. 관련 후보가 없는 새 주제나 안전한 본문 삽입 경계가 없는 글은 해당 추천을 생략할 수 있으며, 이것만으로 배포를 차단하지 않는다.

## 대표 글

대표 글은 인기 순위가 아니라 현재 콘텐츠의 대표 선택이다. 실제 해결 범위·절차·조건과 예외·근거, 분야 분산을 기준으로 선정했다. 조회 성과를 만들어 표시하지 않는다.

| 분야 | 대표 글 | 선택 이유 |
| --- | --- | --- |
| IT·디지털 | 드라이브 공유 권한 | 역할별 차이·사람 지정·링크 범위·폴더 상속·문제 확인까지 이어진다. |
| 생활·주거 | 식기세척기 사용법 | 적재·코스·건조·효율 표시·매뉴얼 점검이 구분돼 있다. |
| 경제·일 | 시트 드롭다운 | 생성·오류 입력·기존 데이터 적용을 표와 절차로 설명한다. |
| 여행·이동 | 지도 오프라인 저장 | 다운로드부터 범위·제한·저장 위치·갱신·출발 전 확인까지 다룬다. |
| 취미·문화 | 포토 백업 | 계정·저장공간·품질·백업 대상·결과 확인을 구분한다. |

홈 상단은 지도 오프라인 저장과 식기세척기 글을 사용한다. 홈 분야별 목록과 카테고리 페이지는 대표 글을 먼저 표시하고 나머지는 기존 발행일 순을 유지한다. 전체 글·검색·최근 글 목록은 기존 기준을 유지한다. `config/navigation.json`의 대표 ID만 바꾸면 적용되며 제목·카테고리·공개 여부는 실제 원고에서 읽는다.

## 실용 자료 보강 검토안 — 아직 적용하지 않음

모든 글에 같은 부록을 붙이기보다 실제 작업에 필요한 자료 한 가지를 선택한다.

| 글 유형 | 검토할 자료 | 검증·유지 기준 |
| --- | --- | --- |
| 스프레드시트 | 소량의 연습용 CSV와 작업 전후 표 | 실제 개인정보 없이 합성 데이터임을 표시한다. 중복 제거 등 결과를 코드로 재계산하고 CSV 수식 실행 문자열을 제외한다. |
| 앱·설정 | 핵심 메뉴 경로와 결과 확인 목록 | 원고와 공식 자료에 있는 이름·기기·조건만 사용한다. 실제 UI처럼 만든 가짜 캡처는 만들지 않는다. |
| 가전 | 증상·조건별 점검표 | 모델별 수치·절감액을 추측하지 않고 제조사 설명서를 우선하도록 구성한다. |

우선 대표 글 한 편에서 샘플 형식을 검토하는 방안을 권한다. 새 원고에서는 별도 AI 호출 대신 기존 생성 응답에 필요한 자료만 포함하도록 설계할 수 있다. 출력 토큰은 조금 늘 수 있으므로 자료 길이를 제한한다. 게시 전 검토와 원고 revision 승인은 그대로 필요하며 기존 32편 전체를 재생성하는 계획은 없다.
