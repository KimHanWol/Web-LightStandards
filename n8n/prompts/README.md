# 원고 작성 프롬프트

기본 작성 프롬프트는 [article-system.txt](article-system.txt)입니다. n8n 본체 `Blog - 소소한 기준`의 `Configuration.article_system_prompt`에 저장하며 `Write Original Draft` 시스템 메시지가 참조합니다. 분량 보완·사실 수정은 같은 Configuration의 해당 프롬프트로 분기합니다. 키워드·카테고리·근거·기존 제목은 `Select Draft`가 별도의 사용자 메시지로 전달합니다.

2026-10-16부터 [처음 접하는 독자를 위한 작성 기준](../../docs/BEGINNER-WRITING.md)을 적용합니다. 필수 준비·용어 풀이·행동 이유·결과 판단을 자연스럽게 연결하고, 부록 추가보다 본문 이해를 우선합니다. 검수도 같은 독자 기준을 사용하되 문체 취향만으로 재호출하지 않습니다.

## 편집 기준

| 항목 | 작성 기준 |
| --- | --- |
| 핵심 답 | 첫 문단에서 답과 적용 범위를 제시하고, 방법보다 긴 경고가 먼저 나오지 않게 구성 |
| 설명의 완결성 | 필요한 행동·조건·이유·결과 확인을 연결하고 처음 나오는 낯선 용어를 풀이 |
| 절 구성 | 각 H2가 서로 다른 질문을 해결하고, 실제 필요한 하위 질문에만 H3 사용 |
| 가독성 | 한 문단 한 내용, 보통 80~160자·2~3문장, 작업은 번호 목록, 비교는 2~3열 표 |
| 자연스러운 문체 | 차분한 합니다체, 구체적인 행동 표현, 체험·추상적인 평가·상투적인 도입 지양 |
| 분량 | 실제 본문 최소 3,500자, 목표 약 4,000자. 핵심 질문에 충분히 답하면 억지로 늘리지 않음 |
| 이미지 | 기본 3장, 필요할 때만 4장. 무료 사진 우선, 부족분만 생성, 주제의 서로 다른 내용에 대응, 특정 문서·책상 소재 강제 제거 |
| 근거 | 입력에 검토된 URL만 사용, 기능·버전·업로드·비용의 적용 범위 구분 |
| 최종 편집 | 답변 누락·근거 대응·중복·어려운 문장·분량·이미지 구성 점검 후 한 번의 응답으로 반환 |

글자 수와 이미지 수는 현재 운영 조건이며 SEO 또는 광고 승인 조건이 아닙니다. 자기 점검이 정확성이나 승인·검색 성과를 보장하지 않습니다.

출력 계약은 기존 `canWrite`, `holdReason`, `title`, `description`, `markdown`, `imagePrompts`, `editorialChecks` 그대로입니다. 보류 응답은 빈 원고·이미지 배열을 포함하며 검사 노드에서 이미지 생성 전에 중단됩니다. 정상 출력도 `needs_review`와 승인 revision 흐름을 거칩니다.

## 점검 방법

1. 로컬 프롬프트와 생성된 draft 노드의 시스템 메시지를 비교합니다.
2. 기존 워크플로 ID를 업데이트하고 다시 읽어 실제 저장값이 같은지 확인합니다.
3. 기존 모델·Credential·예산·비활성 상태와 원고 승인 흐름이 유지되는지 확인합니다.
4. `npm test`로 기존 출력 파서·보류·안전한 출처·예산·발행 검사와의 호환성을 확인합니다.

프롬프트 변경만으로 생성 품질 향상을 실증한 것은 아닙니다. 다음 실제 원고에서 첫 답변, 절별 질문, 문단 길이, 중복과 출처를 대조해 확인해야 합니다. 이 변경 작업에는 별도 유료 생성 호출이나 사이트 원고 재발행을 포함하지 않습니다.

구조화된 지시와 출력 형식의 분리는 [OpenAI Docs의 프롬프트 작성 안내](https://developers.openai.com/api/docs/guides/prompt-engineering)를 참고했습니다.
